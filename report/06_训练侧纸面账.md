# 模块 6：训练侧纸面账

## 做了什么

模块 6 不跑程序，按固定参数算两笔账：70B 模型训练一次的 checkpoint 有多大、按什么间隔保存；训练变慢时先查节点还是先查网络。

## checkpoint 容量

混合精度 Adam 训练的 checkpoint 包含优化器状态，体积远大于权重本身。每个参数占 16 字节：

| 项 | 每参数字节 |
|---|---:|
| fp32 主权重 | 4 |
| fp16 参数副本 | 2 |
| fp16 梯度 | 2 |
| Adam 一阶动量 | 4 |
| Adam 二阶动量 | 4 |
| 合计 | 16 |

70×10⁹ 参数乘 16 字节得 1.12TB。分片存到 1024 张卡，每卡约 1.1GB。

## 分片的理由

每个 rank 只写自己的分片，或者每个 rank 只读自己的分片。让 1024 个 rank 同时读同一个共享对象时，请求全部打到存储的元数据服务上，单对象的元数据查询先成为瓶颈，网络带宽还没用满，作业已经卡住。分片后每个 rank 访问独立的键，元数据压力随分片数摊开，读写都能并行。

checkpoint 的提交协议同样重要：先写临时目录，写完再 rename 成正式名。否则重调度时读到写了一半的目录，加载失败。

## 保存间隔

公式：

```text
T = √(2 × C × F)
```

C 是存一次 checkpoint 的耗时，F 是平均故障间隔。代入 C = 120 秒、F = 14400 秒（4 小时）：

```text
T = √(2 × 120 × 14400) = √3456000 ≈ 1859 秒 ≈ 31 分钟
```

C 与 F 是假设值，本机没有测过存 checkpoint 的耗时。这个公式的含义是：故障越频繁、保存越慢，间隔就该越短，两边取平衡。间隔取 31 分钟时，一次故障平均丢 15 分钟左右的训练进度。

实际取值还要看存储带宽。120 秒的 C 在 1.12TB 规模下需要约 9.3GB/s 的写入带宽，由 1024 个 rank 分摊，每卡约 9MB/s。

## 变慢时的排查顺序

先查单节点自身的三项：CPU 占用、磁盘 IO、数据加载吞吐。三项都正常，再怀疑网络。

顺序反过来的代价是误判。数据加载慢与链路慢在训练日志里都表现为 step 时间变长，先换网卡、换交换机、换节点都解决不了数据加载的问题，每轮替换还要重新跑基线。

collective 的完成时间由最慢的 rank 决定。一个节点的数据加载跟不上，其他节点都在它的 all-reduce 上等，整组 step 时间一起变长。这个特性让"单节点问题"表现为"全局变慢"，也是排查要从单节点开始的原因。

## 结论

1. 70B 模型的完整 checkpoint 是 1.12TB，按 16 字节每参数算，分片后每卡 1.1GB。
2. 保存间隔 31 分钟来自 `T = √(2CF)` 与两个假设值，实际部署先用实测的 C 替换。
3. 训练变慢先查单节点，再查网络。collective 的完成时间由最慢的 rank 决定，单点问题会表现为全局变慢。

## 验收对照

| 条目 | 结论 | 证据 |
|---|---|---|
| checkpoint 容量账 | 达成 | 70B × 16B = 1.12TB，每卡 1.1GB |
| 保存间隔公式与代入 | 达成 | T ≈ 1859 秒，C 与 F 为假设值 |
| 慢节点与网络故障的区分顺序 | 达成 | 先单节点 CPU、磁盘、数据加载，再查网络 |
