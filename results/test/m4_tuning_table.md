# 模块 4：NCCL_ALGO / NCCL_PROTO 单机对比

单节点双卡 A100-SXM4-40GB，PHB 拓扑（无 NVLink），每组只测一档，取 out-of-place 组的 busbw。

| 尺寸 | 配置 | busbw(GB/s) | 相对默认 |
|---|---|---:|---:|
| 1MB | 默认 | 9.49 | — |
| 1MB | `NCCL_ALGO=Tree` | 5.38 | −43.3% |
| 1MB | `NCCL_PROTO=LL` | 3.32 | −65.0% |
| 1GB | 默认 | 14.69 | — |
| 1GB | `NCCL_PROTO=Simple` | 14.61 | −0.5% |
| 1GB | `NCCL_ALGO=Tree` | 14.31 | −2.6% |

六组全部 `#wrong` 为 0，退出码 0。

## 结论

1MB 档强制指定算法或协议都变慢：LL 协议在该机器上比默认低 65%，Tree 算法低 43%。默认配置在这个尺寸下已经选到更合适的组合，强制指定反而破坏了 NCCL 的自适应选择。与"小消息 LL 占优"的常见预期相反，原因是本机两卡经 PCIe 主机桥（PHB）互联，没有 NVLink，LL 依赖的低延迟链路段落落不到直连通道上。

1GB 档三组几乎重合（差异在 0.5%–2.6%），带宽由 PCIe 链路决定，算法与协议换不出差异。这一档的结论是"受硬件带宽上限约束"，不构成调优收益。

双卡规模下该组参数差异不显著，多节点场景的调优结论未实跑。
