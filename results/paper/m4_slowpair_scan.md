# 模块 4：拓扑感知慢 pair 扫描设计

状态：未实跑，原因：无多节点，无 Slurm。

## 目标

在 N 个节点的集群里定位哪一对节点之间的链路偏慢，把"网络不行"收敛到具体节点或具体链路。

## 需要的环境

- Slurm 集群，N ≥ 4 个节点，同型号 GPU。
- 共享存储上放 `nccl-tests` 编译产物和 `process_nccl_results.sh`。
- 每个节点允许作业跨节点启动（`sbatch` 能拿到成对节点）。

## 命令或流程设计

1. 用 `sbatch --array` 对节点两两组合提交作业，每个作业只测一对节点：

```bash
sbatch --array=0-$((N*(N-1)/2-1)) pair_nccl.sbatch
```

作业脚本里按 array index 拆出两个节点名，只起这两个节点、每节点全部卡：

```bash
srun --nodes=2 --ntasks-per-node=<每节点卡数> \
  ./build/all_reduce_perf -b 32M -e 32M -g 1
```

2. 固定 32MB 单档消息。这一档带宽主导，链路慢才现形；小消息受延迟波动干扰，不适合做链路判定。
3. 每个作业输出一份日志，跑完用 `process_nccl_results.sh` 汇总成 CSV，字段至少包含节点对、busbw、是否成功。

## 成功判据

- 全体 pair 的 busbw 分布集中，说明链路一致。
- 低于全体均值约 5% 的 pair 记为慢 pair。
- 交叉比对：某节点参与的所有 pair 都慢，定位到该节点（或该节点网卡）；只有个别 pair 慢，定位到那两个节点之间的链路。

## 为什么没实跑

当前只有单节点、没有 Slurm，成对扫描的前提不存在。设计与 ~5% 阈值判据保留，不写多节点数字。
