# 模块 5 ⑤-3：NVCRE 集群健康认证流程

状态：未实跑，原因：无 K8s + GPU Operator + 多节点。

## 目标

生产作业上线前，对每个节点跑一次标准化认证，把带病节点提前隔离，避免训练跑到一半才暴露。

## 需要的环境

- Kubernetes 集群，GPU Operator 正常，多节点多卡。
- `nvcrectl` 命令行工具与集群连通。
- 节点间网络满足认证测试所需的 collective 条件。

## 命令或流程设计

1. 安装 `nvcrectl`，并让它能访问集群。
2. 初始化认证框架：`kubectl nvcre setup init`，在集群里部署认证所需组件。
3. 提交一个 communication 测试（集群级 collectives 检查），指定目标节点集合。
4. 测试结束后读报告，逐个节点看结论。

## 成功判据

- 报告里每个目标节点都有明确的 pass/fail，失败项附原因（如带宽低于阈值、NCCL 建通信器报错、GPU 不可见）。
- 把某个 fail 节点从测试集合里移除后重跑，该节点不再出现在结果中（或被标红跳过），其余健康节点的结论与上一轮一致。

## 为什么没实跑

当前没有 K8s、GPU Operator 和多节点，认证没有可作用的对象。按验收要求不写认证耗时，只保留流程、报告字段与隔离后的预期结论。
